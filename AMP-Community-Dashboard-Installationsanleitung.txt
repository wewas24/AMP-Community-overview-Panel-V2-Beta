AMP Community Dashboard v2.1.1 – Installation für AMP mit Nginx

Diese Anleitung verwendet die Beispiel-Domain `amp.example.com`.

Voraussetzungen

- Eine laufende AMP-Installation hinter Nginx und HTTPS
- Node.js 22 oder neuer
- Ein Dienstkonto `amp`

1. Dashboard ablegen

   mkdir -p /opt/amp-community-dashboard
   unzip /opt/amp-community-dashboard-v2.1.1-security.zip -d /opt/amp-community-dashboard
   chown -R amp:amp /opt/amp-community-dashboard

2. Erstes Administratorkonto erstellen

   cd /opt/amp-community-dashboard
   sudo -u amp node create-admin.mjs

3. Systemdienst einrichten

   cp /opt/amp-community-dashboard/amp-community-dashboard.service /etc/systemd/system/amp-community-dashboard.service
   systemctl daemon-reload
   systemctl enable --now amp-community-dashboard
   systemctl status amp-community-dashboard --no-pager

Die Ausgabe muss `active (running)` zeigen. Der Dienst lauscht nur auf `127.0.0.1:3100`.

4. Nginx ergänzen

`nginx-security-http.conf` im globalen Nginx-`http {}`-Bereich einbinden. Danach den Inhalt von `nginx-snippet.conf` in den vorhandenen HTTPS-Serverblock von `amp.example.com` einfügen. Die bestehende AMP-Konfiguration für `/` bleibt unverändert.

Wichtig: Keine Zeile `proxy_cookie_path / /uebersicht/;` für das Dashboard verwenden. Der sichere Login-Cookie benötigt `Path=/`.

Dann testen und neu laden:

   nginx -t && systemctl reload nginx

Die Übersicht ist danach unter dieser Beispieladresse erreichbar:

   https://amp.example.com/uebersicht/

5. Erste Einrichtung

- Oben rechts „Anmelden“ wählen.
- Den ersten Server mit seiner AMP-Community-Adresse anlegen.
- Optional mit Vollzugriff die Spielserver-Adresse und den Port ergänzen. Das Abfrageprofil kann auf „Automatisch“ bleiben.
- Für einen öffentlichen Verbindungsbutton die gleichnamige Option beim Server bewusst aktivieren.
- Unter „Überwachung“ optional SMTP mit STARTTLS einrichten und eine Test-E-Mail senden.

Interne Spielserver

Private Netzwerkadressen sind standardmäßig blockiert. Falls Spielserver bewusst im selben privaten Netzwerk liegen, in `/etc/systemd/system/amp-community-dashboard.service` diese Zeile setzen:

   Environment=ALLOW_PRIVATE_NETWORKS=true

Danach:

   systemctl daemon-reload
   systemctl restart amp-community-dashboard

Diese Freigabe nur in einem vertrauenswürdigen Netzwerk aktivieren.
