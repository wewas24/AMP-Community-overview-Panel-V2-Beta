AMP Community Dashboard v2.1.1 – Sicherheitsupdate

Diese Anleitung verwendet ausschließlich Beispielwerte.

1. Daten und bisherigen Projektordner sichern:

   systemctl stop amp-community-dashboard
   cp -a /opt/amp-community-dashboard /opt/amp-community-dashboard-before-v2.1.1

2. Das Update-Paket entpacken und alle Dateien in den bestehenden Projektordner kopieren. Den Ordner `data` nicht löschen oder aus einem Paket überschreiben:

   unzip -o /opt/amp-community-dashboard-v2.1.1-security.zip -d /opt/amp-community-dashboard
   chown -R amp:amp /opt/amp-community-dashboard

3. Die mitgelieferte Dienstdatei nach `/etc/systemd/system/amp-community-dashboard.service` kopieren. Eigene Einstellungen, etwa `ALLOW_PRIVATE_NETWORKS=true`, bei Bedarf wieder bewusst ergänzen.

4. Nginx härten:

   - `nginx-security-http.conf` im `http {}`-Bereich von Nginx einbinden.
   - Den neuen Inhalt von `nginx-snippet.conf` in den vorhandenen HTTPS-Serverblock kopieren.
   - Eine alte Zeile `proxy_cookie_path / /uebersicht/;` entfernen. Sie verhindert den sicheren `__Host-`-Cookie.

   Danach prüfen:

   nginx -t && systemctl reload nginx

5. Dienst laden und starten:

   systemctl daemon-reload
   systemctl restart amp-community-dashboard
   systemctl status amp-community-dashboard --no-pager

Beim ersten Start werden vorhandene Sitzungen absichtlich beendet. Das SMTP-Passwort wird aus der Datenbank in `data/secrets/smtp-password` verschoben und erscheint nicht in Exporten oder neuen Sicherungen.

Wichtige Änderungen

- Spielserver-Adressen bleiben in der öffentlichen API verborgen. Für den Verbindungsbutton muss bei jedem Server „Verbindungsbutton öffentlich anzeigen“ aktiv gewählt werden.
- Nur Vollzugriff kann automatische Erkennung, Spielserver-Tests sowie eine neue oder geänderte Spielserver-Adresse auslösen.
- SMTP mit STARTTLS ist auf die erlaubten SMTP-Ports begrenzt. Standard sind 25, 587 und 2525.
- Der Node-Dienst bleibt ausschließlich auf `127.0.0.1:3100`; der öffentliche Zugriff erfolgt nur über Nginx und HTTPS.
